# 可控 Tutting 姿勢生成器 Roadmap

分類：規劃與進度 · [文件總覽](../README.md)

更新日期：2026-10-02  
開發基準：tutting_3d_simulator_v22.html；TG-1 已由使用者確認測試 OK。  
文件用途：後續開發、範圍確認與驗收。TG-2～TG-4 為規劃，尚未實作；本文不代表已啟動下一階段。

## 1. 目標與原則

從指定基礎姿勢出發，在明確規則內提供多個候選，讓使用者先預覽、再選擇套用，逐步支援幾何、空間與編舞。

- 規則可控：指定部位、旋轉軸、角度集合與改動範圍。
- 結果可解釋：顯示改動關節、規則符合情況與誤差。
- 可重現：相同基礎姿勢、設定、骨架與演算法版本搭配相同 seed，應產生相同結果。
- 預覽不污染資料：套用前不改動正式姿勢；取消可回到原狀。
- 不暗中放寬限制：候選不符合規則就拒絕，搜尋失敗需明確回報。
- 先驗證單一姿勢，再處理姿勢之間的運動；端點符合規則不代表轉場全程符合。

## 3. TG-1：已完成基準

### 功能

- 擷取目前姿勢作為生成基礎，包含身體變換。
- 控制左右肩、上臂、前臂與手掌，共 8 個關節的活動軸。
- 支援角度增量與絕對角度集合。
- 限制最大每軸角度變化及最大改動關節數。
- 以 seed 進行有限次搜尋，提供最多 6 個候選；不足時回報實際數量。
- 排除沒有實際旋轉變化與物理朝向重複的候選。
- 保留未選關節的局部角度；拒絕關節限制修正後違反生成規則的候選。
- 候選切換、預覽／取消、套用、加入 POSE，以及套用後存入姿勢庫。
- 基礎姿勢與生成設定納入專案儲存與歷史；候選為暫存結果，可重新生成。
- 規則變更後拒絕套用舊候選。

### 已知界線

- 此階段不判定平行、垂直、鏡像、碰撞或空間固定。
- 保留局部角度不代表世界位置不動；父關節旋轉仍會帶動下游。
- 播放或會干擾姿勢的 IK、LookAt、律動預覽、碰撞修正等狀態，會阻擋生成／預覽並提示處理。
- 姿勢庫儲存不屬於可撤銷的姿勢歷史操作。
- 搜尋次數有限；找不到候選不等於數學上不存在解。

### 驗證紀錄

- 曾以 150 組 seed、共 900 個候選檢查可重現性、部位／軸限制、改動上限與拒絕條件。
- 已檢查預覽取消、明確套用、加入 POSE、設定保存與舊候選失效邏輯。
- 上述自動測試為邏輯測試，非完整瀏覽器渲染驗證；使用者後續實測確認 OK。

## 4. TG-2：幾何約束

### 預期操作

擷取基礎姿勢 → 選擇可動部位 → 加入幾何規則 → 生成 → 查看候選與各項誤差 → 預覽 → 套用。

### 建議拆分

| 子階段 | 工作 | 交付與驗收 |
| --- | --- | --- |
| TG-2.0 | 骨架座標與肢段定義 | 明確定義角色正面、左右方向與肢段端點；角色轉身或鏡頭旋轉不改變幾何判定 |
| TG-2.1 | 正面平面、平行／垂直 | 可選指定肢段及角度容許誤差；逐條顯示誤差與通過狀態 |
| TG-2.2 | 左右鏡像 | 以角色中線平面檢查左右對應肢段／端點；不直接假設兩側 Euler 數值取負即可鏡像 |
| TG-2.3 | 候選搜尋與整合 | 所有啟用規則共同驗證；有限搜尋、失敗資訊、儲存／Undo／Redo 完整整合 |

### 規則定義

- 正面平面：先使用角色空間的固定參考平面，明確定義原點與法向；鏡頭空間規則留待後續。
- 平面限制應指定檢查端點位置或肢段方向，兩者不可混用；位置容許誤差建議依骨長正規化。
- 平行／垂直：以骨骼端點形成的肢段向量計算；平行需標示同向或允許反向。
- 鏡像：以角色中線平面反射後比較對應端點／方向；手掌方向需另定局部參考軸。
- 平面、角度與鏡像容許誤差皆可設定，數值顯示單位須一致。
- 評分只排列已通過規則的候選，不以較高總分掩蓋某條規則失敗。

### 驗收條件

- 人工建立已知平行、垂直、偏離平面的姿勢，誤差計算符合預期。
- 旋轉鏡頭與移動角色時，角色空間規則仍穩定。
- 複合規則、無可動軸、衝突角度與無候選情境皆有清楚結果。
- 預覽取消、專案重載、Undo／Redo 與 seed 重現性通過。
- UI 明確提示：本階段只驗證候選端點姿勢，尚未保證轉場全程。

## 5. TG-3：空間固定與 IK

### 建議範圍

- 優先支援左右手的目標位置固定，再增加手掌方向固定。
- 明確區分世界空間固定與角色空間固定；移動身體時，兩者效果不同。
- 利用既有手臂 IK 解位置；方向約束需處理腕部與上游關節的分配。
- 將求解結果再通過關節限制及 TG-2 幾何驗證，避免最後修正破壞先前規則。
- 回報位置、方向、幾何殘差與求解狀態，設定最大迭代次數與停止條件。

### 開發順序與驗收

1. 單手位置固定：活動肩／肘時，手的目標位置誤差低於設定容許值。
2. 單手方向固定：方向誤差可量測，並與位置限制共同驗證。
3. 雙手與複合約束：所有鎖定目標共同求解；不可達目標不提交。
4. 整合預覽與歷史：取消還原、套用、儲存、重載皆保持一致。

原本 TG-1 為避免干擾而阻擋的 IK 功能，需要有明確的生成求解路徑；不得僅取消衝突提示便視為整合完成。

## 6. TG-4：多步 Combo

### 功能規劃

- 設定步數、每步拍數、Easing、部位／規則及 seed。
- 每一步以前一步候選為基礎，生成連續姿勢。
- 避免重複與無效變化；用角度改動、幾何與空間誤差排序有效序列。
- 可整段預覽、取消或確認；確認後批次加入 POSE 時間軸。
- 明確顯示某步失敗與搜尋預算，預設不將未完成序列寫入正式時間軸。

### 驗收條件

- 相同輸入與版本產生相同序列。
- 每個端點符合該步規則；批次加入可一次撤銷與重做。
- BPM、拍數與 Easing 正確對應播放時長；匯出／匯入後可重現編排。
- 另行驗證轉場：以時間取樣檢查過程中的約束與碰撞，標明取樣精度及侷限。
- 若要求全程空間固定，需逐幀求解或約束導向轉場，不能只用端點 Slerp 保證。

## 7. 共通工程事項

| 項目 | 建議 |
| --- | --- |
| 資料版本 | 後續新增生成器 schema 與演算法版本，定義舊專案缺少欄位時的預設值 |
| 搜尋效能 | 設定搜尋／迭代上限、顯示進度，必要時分批執行並支援取消 |
| 規則衝突 | 回報未通過項目與最佳誤差；不可將有限搜尋失敗宣稱為無解證明 |
| 碰撞 | TG-1 無碰撞驗證；需另外定義偵測模型、容許接觸與驗收範圍，再納入候選驗證 |
| 歷史與保存 | 明確區分暫存候選、正式姿勢、時間軸和姿勢庫；批次操作建立完整撤銷範圍 |
| 測試 | 幾何數學測試、生成規則測試、狀態／儲存測試與實際瀏覽器操作驗收 |
